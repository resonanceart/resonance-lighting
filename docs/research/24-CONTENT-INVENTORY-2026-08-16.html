The build-nothing-new line

What can be a dashboard today, what needs one Ben decision, what stays out

Dashboardable now — zero new firmware

  • Fleet census: every living light, last-heard honesty windows
  • Battery health: mV / mA / SoC + BQ25628E charger truth per light
  • Firmware rollout progress (registry + OTA records)
  • Lifecycle / power tier / active program (60 s cadence)
  • Commissioning provenance per MAC (285 bring-up records)

Needs one Ben decision each

  • Program truth at 1 Hz — bridge mode choice (Q1); text mode drops choreo
  • Self-location — flip on NB_NEIGHBOR_REPORT (defined, not sent)
  • Sensor visibility in normal ops — ToF/tilt/sway/BMP are maintenance-only today
  • Wall-clock / time quality — NB_TIME_QUALITY reserved (ADR 0031)

Explicitly out

  • Bulk direct-frame control — Ben's log: "not treated as proof"
  • Anything lease-based — "ordinary lighting remains deliberately leaseless"
  • Audio direct frames on current firmware — live filter bug (Q6)
  • Any second OTA writer — the 08-16 competing-writer incident

Bridge serial verbs (text mode, 115200)

  • READ r status line · t JSON bridge stats
  • BLINK i[id][:s] / I identify one / all
  • CONFIG c resume · +/- R<hz> rate · F profile (persists!) · m VINDPM · C capacity (reboots) · G charge cap · D drawdown
  • OPS U[id] 35 s maintenance burst · K<id>:<ms> solenoid · S[s] sleep · P<id> park

Reliability built in: broadcast ×4 @5 ms, targeted ×6 @8 ms. Ben's net_bench_dashboard.py ships a validated allowlist of these — the precedent the Mirror's command fence follows.

Fixture-side surfaces

  • USB serial CLI — t full telemetry JSON READ · r status READ · plus config verbs (C G O N L F H) and ops verbs (u maint, K strike, S sleep, X PROTECT clear)
  • HTTP, maintenance mode only — four routes: / banner · /telemetry READ · /resume CONFIG · /update OTA OPS, unauthenticated (the competing-writer incident). Window self-expires at 10 min.
  • Bench firmwares add — led_studio /state·/set · presence_bench /api/frame · led_sol_bench /probe_strike

Live data inventory

What a light tells us, at what cadence

Heartbeat short · every 5 s (field) / 1 s (commission), ±30% jitter

batt mV · batt mA · SoC (255 = no gauge) · reset reason · mode · dl_pdr‰ · dl_rssi · supply mV/mA/good

Heartbeat full · every 60 s ±30%

+ fw_rev · maint_status · lifecycle phase · BQ25628E charger registers · configured capacity/charge · profile · life_state · power_tier · active_program · night_min

Choreo state · 1 Hz — binary bridge mode only

program_id · state · intensity · phase_ms · flags (power-limited / lease / commission)

Text-mode bridge drops this entirely → program truth goes 60 s stale. The core of Question 1.

Maintenance / USB only · ~60-key telemetry JSON

full sensor block (ToF depth/confidence · tilt · sway · BMP temp/pressure) · OTA partition + state · heap · solenoid counters

No path to sensor data during normal fleet operation — a Ben decision away.

Honesty rules the Mirror inherits. Heartbeat tails 5/10/12 always arrive as valid zeros the fixture never populates — render "—", never 0. soc=255 means no gauge reading. null ≠ 0: a running fixture reports life_state=null while a dormant one reports real values. Two firmware naming schemes are live in the field (fixture-* and fx-*). Census counts are a function of listen time — never quote one without its window.
